# Agent instructions

1. **Read the [Master Project Context](docs/MasterContext.md) first.** This is required before planning, delegating, editing, or testing motor work. Recheck the relevant section when a requirement is unclear or the plan changes. Include this instruction in every motor handoff. When available, consult the CSEN701 Project 3 brief (pp. 5–6) for the course requirements and the workspace's full master document (`context.md` beside the checkout) for evidence.
2. **Keep motor work within its ownership.** Work in `drivers/motor/`. Use the [team ownership map](docs/TeamDivision.md) for changes that need a teammate. Before planning any GPIO work, compare the master context, the [pin map](docs/PinMapping.md), and [`AppConfig.h`](include/AppConfig.h). Bring conflicting assignments, new pins, or proposed reassignments to the project owner for approval before choosing or applying a change.
3. **Start with the simplest solution.** Reuse the existing motor contracts. Add abstractions or dependencies only when the task requires them.
4. **Verify the result.** Run the relevant existing checks and exercise at least one boundary or failure case beyond the normal path. Report build, test and bench evidence separately. For documentation-only changes, verify the links and claims against their sources.
